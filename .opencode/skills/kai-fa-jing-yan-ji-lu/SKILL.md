# 开发经验记录

本skill用于将开发过程中获得的经验增量记录到 `docs/开发经验.md` 文档中。

## 触发条件

1. **自动触发**：在卡牌开发或修改过程中，涉及了卡牌开发skill（ka-pai-kai-fa）未提及的实现方法，且从原版代码、API代码或用户提示中完成了开发时，应主动调用此skill记录经验。
2. **用户触发**：用户主动要求将经验记录到文档中时。

## 记录流程

### 1. 判断是否需要记录

检查当前开发中涉及的方法是否已在 `docs/开发经验.md` 中被记录过：
- 读取 `docs/开发经验.md`，查看目录和内容章节
- 如果已有类似经验记录，则在对应章节中补充案例，不新建章节
- 如果没有类似记录，则新增一个二级标题章节

### 2. 记录内容格式

每条经验记录必须包含以下三项内容：

- **用户原始需求**：描述用户想要实现什么
- **实现方案**：具体的代码实现方式或解决步骤
- **方案来源**：如何了解到该实现方案，可选值包括：
  - 查找杀戮尖塔2游戏代码（说明参考了哪个原版卡牌/类）
  - 查找BaseLib库代码（说明参考了哪个类/方法）
  - 用户提示
  - 构建发现问题
  - 其它（需说明）

### 3. 文档结构

`docs/开发经验.md` 的结构如下：

```markdown
# 模组开发经验
该文档记录模组开发中遇到的未见过的情况和解决方案

# 目录

- [1. 经验标题一](#1-经验标题一)
- [2. 经验标题二](#2-经验标题二)

# 内容

## 1. 经验标题一

**用户需求：** ...

**实现方案：** ...

**方案来源：** ...

> 案例：[可选，补充说明]

## 2. 经验标题二

...
```

### 4. 操作步骤

1. 读取 `docs/开发经验.md` 当前内容
2. 判断是新增章节还是在已有章节中补充案例
3. 若新增章节：
   - 在目录中添加对应的链接条目（编号递增）
   - 在内容区域的末尾添加新的二级标题章节
4. 若补充案例：
   - 在已有章节末尾添加 `> 案例：` 补充说明
5. 写入更新后的文档内容

## 注意事项

- 记录是增量的，不要覆盖或删除已有内容
- 章节编号要按顺序递增
- 目录链接必须与内容章节标题一致
- 代码片段使用代码块格式包裹
- 保持描述简洁清晰，便于后续查阅
